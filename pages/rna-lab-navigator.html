RNA Lab NavigatorRNA Lab Navigator

Retrieval-augmented research assistant for literature triage in a wet-dry lab

Django React Weaviate BM25 OpenAI GPT-4o Docker RAG

Laboratory Knowledge Management

RNA Lab Navigator is a retrieval-augmented question-answering app built for an RNA biology lab, where much of what the lab knows is spread across theses, papers, protocols and experimental notes. It was deployed for the lab on the institute network in July 2025.

Questions in plain English go to keyword (BM25) retrieval over a Weaviate index, with an LLM (OpenAI GPT-4o in the lab's code) answering from the top passages; the source documents are listed under each answer. When none of the passages is relevant, the prompt allows a general-knowledge answer that says it is not from the documents.

A public demo on 30 openly licensed documents is being evaluated with a 60-question test set; results and a video will be added here.

Technical Architecture

A React frontend and a Django REST backend, with Weaviate as the document index and Redis as the cache. In the July 2025 local deployment they ran in Docker containers. The details on this page are from the lab's code as of June 2025.

Frontend (React)

  • React 18 single-page app in JavaScript (JSX), built with Vite
  • Tailwind CSS with Headless UI components and Heroicons, and a dark mode
  • Sign-in state and display settings held in React context
  • Each question is one REST request to the backend, answered with one JSON reply

Backend (Django + DRF)

  • Django 4.2 with Django REST Framework
  • JWT sign-in (Simple JWT), with refresh tokens rotated and blacklisted on the server
  • Redis cache: an identical question asked again within an hour is answered from the cache

Retrieval and Answering

  • Weaviate index of the documents' passages, each with its title, author and year
  • Keyword (BM25) search over each passage's text, title and author
  • The 4 best-matching passages, up to 10,000 characters, go into the prompt
  • OpenAI GPT-4o writes the answer from them, capped at 500 tokens
  • Each answer lists up to 3 source documents (title, author, year)

Infrastructure

  • Docker containers on a MacBook, served on the institute network (July 2025)
  • Security and error logging, with each request's response time stored in the app's database

RAG Implementation

The documents are split into passages and indexed once. For each question, passages are retrieved by keyword, and the model answers from them.

1. Document Ingestion

Text extracted from the lab's PDF theses and papers

2. Chunking

400-word passages overlapping by 100 words; theses split by chapter first

3. Indexing

Each passage stored in Weaviate with its document's title, author and year

4. Keyword Retrieval

BM25 search over each passage's text, title and author; the top 4 go to the model

5. Answer

The model answers from those passages, and the app lists up to 3 of their source documents

Access

The app's pages ask lab members to sign in (JWT); accounts are created by an admin or PI, with no self-registration. In 2025 the app was served only on the institute network.

Authentication

  • JWT access tokens that expire after 15 minutes
  • Refresh tokens rotated and blacklisted on the server
  • Brute-force protection (django-axes): a one-hour lockout after 5 failed sign-ins

Network Access

  • Served on the institute network
  • Accounts given to lab members

Deployment Challenges & Solutions

Hosting was tried on several platforms before the app was deployed locally on the institute network.

Platform Evaluation

Evaluated Railway, Render, PythonAnywhere, and Vercel for hosting, each presenting unique constraints.

CORS & Authentication

Resolved complex cross-origin resource sharing issues between distributed services. Implemented dynamic CORS configuration to handle Vercel's changing deployment URLs while maintaining security.

Performance Optimization

Repeated questions were answered from a one-hour Redis cache, and the prompt was kept small: the 4 best-matching passages (down from 5), at most 10,000 characters. Answers were capped at 500 tokens.

Local Deployment

Deployed in July 2025 in Docker containers on a MacBook on the institute network, serving 25 documents (7 PhD theses, 18 papers) to lab members at an institute IP address.

Real-World Applications

Literature Review Acceleration

Lab members can query the indexed papers and theses in plain English. Each answer lists up to 3 source documents (title, author, year) from the passages the model was given.

Finding Methods

Lab members can ask how a method was done in the indexed theses and papers, and the answer lists up to 3 of the documents its passages came from.

Thesis Knowledge Preservation

Theses hold much of what a lab learns, and that knowledge is easily lost after graduation. The lab's PhD theses are indexed chapter by chapter, so later students can ask questions of earlier students' work.

Engineering Insights

Deployment Platform Selection

Free tier limitations significantly impact architecture decisions. Evaluating multiple platforms (Railway, Render, PythonAnywhere) taught valuable lessons about balancing cost, features, and performance requirements.

RAG System Optimization

Balancing accuracy with performance requires careful tuning. The app sends the model the 4 best-matching passages, down from 5, to cut response time.

User-Centered Development

What developers think users need often differs from actual requirements - continuous feedback loops are essential.
